## 2024-04-25 - Analytics Database Query Overfetching Anti-Pattern
**Learning:** Found an anti-pattern in `app/api/analytics/*` routes where `new PrismaClient()` is improperly instantiated and `findMany()` is used to fetch all records into Node.js memory just for aggregate counts, leading to potential memory bloat, high latency, and DB connection exhaustion.
**Action:** Always import the shared singleton `import { prisma } from '@/lib/prisma';`. Use database-level aggregations like `prisma.parcel.groupBy()` with `_count: { _all: true }` and accumulate mapped fallback keys in memory to minimize database transfer latency and Node.js memory footprint.

## 2024-05-29 - Prevent DB Overfetching in List Views
**Learning:** Overfetching full relational objects (e.g., `ratings`, `matches`) just to access their `.length` in list API endpoints (like `app/api/contractors/route.ts`) wastes bandwidth, memory, and database processing.
**Action:** Use Prisma's `include: { _count: { select: { ratings: true } } }` to retrieve just the counts. Calculate averages via a separate `prisma.model.groupBy` query with `_avg` to keep heavy computation in the database, reducing the payload and N+1 query patterns.
## 2024-06-11 - Optimize Nested Aggregations with Targeted Select and Remove Unused Queries
**Learning:** In Prisma queries involving nested relations (e.g., `include: { units: true, transactions: true }`), eagerly fetching all related records into memory can cause massive performance bottlenecks and memory bloat, especially on analytical endpoints (`/api/properties/stats`). Replacing `include` with targeted `select` blocks (fetching only the specific fields needed like `amount` or `status`) drastically reduces database transfer payloads. Additionally, unused queries decoupled from the API response (like `monthlyTrend`) can stealthily degrade performance without any visible impact.
**Action:** When auditing analytical API routes, meticulously check how the fetched records are utilized in the final response payload. Swap `include` for `select` wherever possible, and ruthlessly delete unused queries entirely to save unnecessary database operations.
